\section{Security and Privacy Considerations}
Manager routes require a signed HttpOnly session cookie, and direct backend calls require an internal secret header that only the server-side proxy supplies. Secrets come from environment variables. No biometric identifiers are stored, and the local demo credential rule is for development only and must be replaced by real authentication before any deployment.

Floor footage, calibration frames/configuration and generated diagnostics remain local under Git-ignored data directories. The report includes only selected local demonstration frames; no footage upload, persistent person crops or facial-identity records are required by the prototype.

\section{Current Limitations}
\begin{itemize}
\item Vision-derived dashboard metrics still use prototype or demo data, and the agent status page shows mock data.
\item The pipeline is offline/batch, not real time.
\item Camera handoff covers only cam1 right exit to cam2 left entry, and it is not full re-identification.
\item Single store only, and POS data comes from file import.
\item Demo authentication accepts any valid email and a password of six or more characters.
\item The temporary floor calibration uses estimated dimensions and approximate screenshot correspondences; all distance outputs are provisional/approximate.
\item The sampled moving clip supported only the reference snapshot. Whole-clip metric coverage and motion compensation are not established.
\item Box-bottom proxies can be wrong for seated or occluded people, including those in the reference-frame pair.
\item Trained role detection and metric outputs are available through CLI, but their integration with temporal interaction events and the dashboard remains pending.
\end{itemize}
